# 凌霁日常造型与私人舱室

版本：v0.1，2026-09-04。当前范围为视觉设计与素材说明；未来技能、战斗算法与解谜仅列方向，不改技能代码、不添加数值系统。本轮未运行测试、未启动 Godot。

## 体验目标

让玩家看见成年凌霁脱离任务装备后的放松状态，以及属于她自己的安全空间。日常服不是受伤惩罚或罗茂支线的奖励，也不以侵犯隐私来展示角色身体。

## 宽松休闲睡衣立绘规范

保留现有凌霁的脸型、发色、发型与主要识别色；不因换装改变成年身份或塑造幼态。选择宽松、非透明、正常覆盖的长袖上衣与长裤，圆领或自然翻领，不刻意低胸、贴身或露出内衣。柔软棉织感、少量科幻功能缝线与袖口标识，将基地设定融入日常服，而不是把睡衣做成铠甲。

默认姿态：肩膀放松、双臂自然垂放或单手拿杯，完整站立轮廓便于对话 UI。背景独立或透明，避免把卧室直接烘焙成立绘背景。表情不含被迫顺从、羞辱或情色化惊慌。

## Q 版规范

用途：房间内站位、日常对话小图标与未来短动作参考，不自动等于可行走资产。

保持成年角色特征，采用简洁圆润的头身比例、宽松上下装和清晰发型轮廓。建议姿势为自然站立、挥手、思考、伸展；不加入床上展示动作。正面/侧面/背面的造型须保持服装结构一致。当前姿势图只能当概念资产；若以后制作四向行走图集，须另行规定网格、脚底锚点、每帧尺寸和步态，不能直接把一张姿势拼图当 SpriteFrames。

## 六种表情

| 表情 | 视觉重点 | 日常用途 |
| --- | --- | --- |
| 平静 | 自然眉眼，放松嘴角 | 房间待机、阅读日志 |
| 微笑 | 轻抬嘴角、目光柔和 | 与可信同伴通话、自主休息 |
| 思考 | 眉间轻收，视线侧移 | 核对线索、阅读算法提示 |
| 惊讶 | 双眼稍睁，嘴微张 | 收到意外任务信息，不用夸张恐惧 |
| 警惕 | 目光集中，眉尾压低 | 不明门禁请求、可疑记录 |
| 坚定 | 目光正对，嘴线明确 | 拒绝越界、决定出发 |

表情图统一头部角度、镜头距离与光源，便于未来替换头像。脸部表情不改变睡衣领口或身体姿态来暗示额外含义。

## 卧室：科幻基地私人安全空间

构图为适配 2D RPG 的俯视/高位平地房间：床、工作桌、个人终端、储物柜、灯具、小型生活物件与入口门禁。入口至桌前、床边留连续行走空间；床和柜体是潜在碰撞对象。使用基地冷灰结构与温暖床头灯形成休息感，不做华丽酒店或战斗竞技场。

门禁边界明确：门口终端、访问请求灯与关闭的门作为视觉信息。私人房间不会默认允许 NPC 进入；将来若接入互动，进入须由凌霁明确回应。罗茂越界的证据仍应通过审计记录呈现，不能把卧室当作供偷窥的场景。

当前房间图片是环境素材，不代表地图碰撞、导航、互动点或存档位置已经实现。以后做可行走地图时需将入口、家具与走道对齐真实角色尺寸，再确认遮挡与碰撞。

## 本批素材交付类型

- 日常全身立绘：对话展示；不带地图背景。
- Q 版姿势图：造型和站姿参考；不是完整行走动画。
- 六表情图：头像变化参考；切图与运行时映射须另行接入。
- 俯视卧室图：基地私人空间背景；地图功能须单独制作。

文件名、具体尺寸与是否已接入由素材/代码交付记录确认，不在本设计中虚构完成状态。

## 未来三个短谜题方向（均未实现）

### 1. 通讯线路路由

目的：把地区探索所得端口信息用于打开合法通路，让玩家感到理解基地结构。
输入：在有限端口间选择连线，避开标为故障的节点。
输出：找到一条从授权入口到目标设备的有效路径；未来可关联战斗中的干扰技能或关闭一条敌方增援链，但不凭空新增技能。
算法思想：图路径、可达性与受限路由，不要求玩家写代码。
边界／失败：无效路线明确显示断点，可立即重连；主线提供提示或替代探索路径，不因拒绝罗茂而无解。没有隐藏倒计时或资源罚款。

### 2. 审计事件排序

目的：让玩家自己识破“先扣留告警、后私人援助”的因果关系。
输入：排列少量带时间线索的访问、告警、发送记录，满足已知先后约束。
输出：得到可核验事件链；未来可关联战前侦察、看穿敌方行动先后，但不改变当前罗茂证据流程。
算法思想：偏序与拓扑排序，允许多个满足约束的正确顺序。
边界／失败：冲突只标出矛盾的一对记录，允许撤销；没有错误一次销毁证据或永久坏结局。

### 3. 机库有限状态机

目的：让“观察状态再执行动作”同时服务解谜与未来战斗教学。
输入：按面板可见状态选择断电、校验、授权、启动等已有语义操作。
输出：把装置从锁定状态带到安全启动；未来可借用敌人蓄力、暴露、恢复的状态提示，帮助理解打断窗口。
算法思想：有限状态机与合法转移，不需要新增复杂编程界面。
边界／失败：非法转移解释缺少的前置状态，保持可重试；不偷偷损坏装备。任何技能联动都须在未来获准实现时再设计。

三个谜题暂不指定奖励、伤害、冷却或成功率，不为未实现系统添加调参表。下一步应先选择一个地区与现有机制的具体接点，再制定可验证的玩法方案。
