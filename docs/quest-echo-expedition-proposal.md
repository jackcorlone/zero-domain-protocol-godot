# 《零域协议》新区域设计：飞船舱与「灰潮盆地」

状态：用户确认后，已实现首版可玩外勤（2026-08-30）。本文保留设计目标；具体落地范围、入口与测试结果见 [试玩说明](echo-expedition-playtest.md)。

## 1. 这一章要带来的变化

基地是整备与接任务的据点，野外是玩家自主调查的空间。玩家不必按照固定顺序访问所有地点，也不必清光怪物才能完成任务。

沿用 Godot 的 2D 俯视探索、小角色四方向移动、对话大立绘和独立回合制战斗。飞船承担区域间交通，不要求改成 3D 飞行游戏。

首版采用地球上被从地图中删除的冰原遗迹「ECHO-9 / 灰潮盆地」。飞船执行短途地表航行，不在本章直接扩展成星际旅行。

首版目标：一段约 20–30 分钟的外勤任务。自由度来自路线、探索顺序、战斗回避与任务处置，不先做无限大的开放世界。

## 2. 剧情接续：来自基地外的回声

完成「静默回路」后，基地的对外监听阵列捕获一次与异常认证相同的信号。它来自基地外，而不是已知驻站。

这不是推翻“核心区下方”的线索：基地外的接收端可能是另一段链路。完整记录路线能提前识别信号特征；部分记录路线需现场验证。两种旧结局都能开启新任务。

沈砚：

> “这个坐标在所有现役地图上都是空白，但那里刚刚回应了你的识别码。乘‘游隼’过去，确认信号源。别把调查变成清场——我们需要知道那里发生过什么。”

任务名：**回声之外**。

任务目标：在未知区域取得两份可交叉验证的定位线索，找到观测站，决定如何处理信号记录，然后返回基地汇报。

## 3. 出发流程：电梯 → 飞船舱 → 登舰

### 飞船舱不是一个传送按钮

基地电梯保留 B7，新增「H1 飞船舱」楼层。舱内可以实际走动：

- 舱口左侧：升降梯，可回指挥中心。
- 中间：停泊中的小型登陆飞船「游隼」，舷梯是登舰入口。
- 右侧：整备柜，可以查看背包、换装和购买标准补给。
- 飞船尾部：工程员 NPC「岑遥」，提供环境提示和一段可选对话。
- 舷梯旁：航行终端，显示任务简报、目的地和已知风险。

岑遥：

> “下面的电磁雾会吃掉远程导航。飞船能保住落点，但进了盆地，要靠你自己认路。发现旧灯标就修好，它们比地图可靠。”

登舰时给出「立即出航 / 再整备一下」，不会踩到门口就自动出发。任务开放后不额外收燃料费，避免玩家花光信用点后无法推进。

首版用短暂、可跳过的 2D 航行过场表现出发和穿越云层。暂不增加手动驾驶、空战或大型飞船内部地图。

## 4. 地图：三条探索支路与一个汇合目标

```text
指挥中心 ─ 电梯 ─ H1 飞船舱
                       │ 登舰 / 出航
                       ▼
                 A. 飞船着陆点
                /      │      \
       B. 断讯高地 ─ C. 坠毁货船 ─ D. 裂隙栈道
                \      │      /
                  E. 废弃观测站
                       │
                 回到着陆点撤离
```

这是连通关系，不是三个弹窗选项：每条路都需要人物实际行走，有岔路、遮挡、可绕行的敌人和可调查物。B、C、D 可任意顺序探索，不是选一条就永久关闭另外两条。

首版拆成数张连接的 2D 小地图，每张约 1–2 屏，使用跟随镜头与地图边界。场景入口提供明确标识，回头能走回上一张地图，不做看不见的单向门。

| 地点 | 玩家看到什么 | 可做的事 | 对后续的实际影响 |
| --- | --- | --- | --- |
| A 着陆点 | 飞船、导航灯、碎冰与旧公路 | 与岑遥通讯、看任务、登舰撤回 | 安全据点；允许中途回基地，再来时保留调查进度 |
| B 断讯高地 | 倒伏天线和仍在闪烁的旧灯标 | 校准天线、读取时间戳、修复灯标 | 获得定位线索；修好灯标后地图标出附近道路 |
| C 坠毁货船 | 裂开的船体、货箱、求救声 | 搜索舱室、救援受困维修员、调查运输单 | 获得定位线索；救援者指出观测站维护入口 |
| D 裂隙栈道 | 断桥、巡逻机、废弃维修箱 | 绕行、战斗、修桥、找箱子 | 获得定位线索；修桥后形成回着陆点的捷径 |
| E 废弃观测站 | 被冰封的控制室和仍工作的信号核心 | 选择进入方式、阅读记录、处置信号 | 完成主目标；处置方式改变汇报与区域状态 |

### 线索规则

B、C、D 各有一份定位线索，任取两份即可确定观测站坐标；第三份是可选探索。地图边界不因未收集线索而出现空气墙，玩家提前走到观测站也可以查看外部、发现入口，只是无法完成信号身份核验。

三份线索各有固定来源标记，不可反复读取同一个终端凑数。线索是任务记录，不占用背包容量。

## 5. 让交互产生变化

### 例一：断讯高地的灯标

查看天线旁的检修铭牌，可以得知三段波形应依次为「短—长—短」。玩家调整三个开关并确认，错误只重置输入，不扣 HP/MP。

恢复灯标前提示：“启动会暴露位置，引来附近巡逻机。”

- 启动：地图显示更多道路，但一台可绕开的巡逻机向灯标靠近。
- 只下载本地记录：仍取得定位线索，不获得道路标记，也不惊动巡逻机。
- 暂时离开：保留现状，可以以后回来处理。

这样，交互改变可见地图与敌人位置，而不是只增加一句日志。

### 例二：坠毁货船的求救声

受困维修员不知道基地仍有人存活。他的身份暂时只通过胸牌与运输单交叉确认，不直接宣布是反派或失忆关键人物。

玩家可以先核验身份、通过手动门锁解谜救人，或先拿走外侧运输单后继续调查。救援不消耗不可替代的钥匙；MP 为 0 也能完成。

救出后，他在着陆点出现，透露观测站维护通道的位置。没有救人也能推进主线，只是必须自行寻找维护口或面对正门守卫。首次离开前显示求救尚未处理，避免玩家误以为已完成救援。

### 例三：断桥与装备箱

正面道路有可见的巡逻机。旁边的旧检修坡道通向桥梁控制箱，玩家可以绕远、观察路标并修桥。

- 正面：路线较短，进入警戒范围后可交战；进战斗前提示。
- 侧道：走得较远，有两处方向线索和一处顺序机关，不强制战斗。
- 修桥：永久打开回着陆点的短路，不随重新进入地图关闭。
- 隐藏宝箱：放在旁支而非主线必经路；一次性获得一件区域专属模块。具体属性在实现前另定，避免现在随意叠加战斗倍率。

## 6. 观测站：不强制打 Boss

取得两份定位线索后可以核验控制台。进入方式有三种：

1. 正门：与守卫交战，胜利后进入。
2. 维护入口：通过救援情报或外墙可发现的检修标记找到，完成门锁机关后绕过正门守卫。
3. 身份协商：带着定位线索和货船运输单与守卫终端对话，指出认证矛盾，取得一次性调查许可。

三种方式都必须让玩家在场景里找到相应入口/终端，不能只在同一个弹窗里选择“战斗或潜行”。维护入口不能要求先打败它原本要绕过的守卫。

观测站最终记录：

> “LYRA-7 的返航请求已获批准。”
>
> 时间戳：三年前。发送地点：SITE OMEGA。

这是新的谜团，不当场确认凌霁的过去、克隆人或时间旅行等重大真相。

### 任务处置

- **复制记录，保留信标运行**：带回完整遥测，区域继续有活动信号。回基地能追踪下一次回应，野外警戒不解除。
- **复制静态档案后关闭信标**：保留已经读到的档案，但放弃后续实时追踪；附近受信标控制的巡逻机停机，返程更安全。

在确认前列出可预期结果，并提供取消。两条路线都能完成任务并获得同等基础任务奖励，不把“选择不一样”直接等同于“一个选项明显更亏”。救援、修桥、额外记录各有独立的可选结算，不要求做完全部支线才准回家。

## 7. 返回与再次探索

- 玩家可在最终任务完成前回到飞船撤离，恢复到基地整备；调查、救援、开箱、开路状态保留。
- 完成任务后不强制瞬移。玩家可以继续搜图，或沿修好的捷径返航。
- 再次出航会看到已经救走的 NPC 不再被困、桥保持修好、箱子保持打开、关闭的信标不会自动恢复。
- 普通刷怪点与一次性守卫分开记录。任务守卫不刷新；普通敌人仅在返回基地后重新出航时刷新，并在地图上明确属于可重复遭遇。
- 本章不做全局倒计时、饥饿或强制燃料消耗。第一次尝试以观察、选择与发现为重点。

## 8. 美术和界面方向

H1 飞船舱：开阔机库、浅色地坪、橙色引导线、蓝白飞船，玩家从侧面走上舷梯。仍用二维背景和二维角色，不用 3D 模型拼出与现有画风不同的关卡。

灰潮盆地：灰白碎冰、暴露的黑岩、风化的工业残骸，局部有青绿色微光苔。远处云雾和极光只作背景层；可走区域和障碍轮廓清楚，避免又变成一片难辨道路的深色室内地图。

界面以小地图、当前位置和一条当前目标为主。支线在发现后才显示，不在开局把整张地图塞满任务图标。按 E 交互、按 C 人物、按 M 地图沿用原操作。

地图小角色与战斗大立绘继续分开使用；飞船、NPC 和野外敌人都需要对应的二维素材。此设计稿没有生成或交付这些资产。

## 9. 首版实现范围与接入注意

首版：一个可行走机库、可跳过的飞行过场、五个相连区域、三条定位支路、一个救援事件、一处修桥捷径、一只解谜箱、观测站三种进入方式、两种任务处置、往返与存档。

不包含：自由驾驶飞船、多个星球、程序化地图、全开放世界、日夜生态模拟，以及尚未确认的重大身世揭示。

现有代码的接入点：

- `exploration.gd` 的电梯目前只处理 B7；新增 H1 目的地时必须保留旧权限判断，已完成旧主线的存档能够直接接新任务。
- 当前地图切换只有 command / b7 两种。野外需要独立场景和出口，而不是让新地点落进 B7 的默认分支。
- `player.gd` 当前按 1280×720 单屏范围钳制坐标；新地图的移动边界要跟随地图实际尺寸，并接入 Camera2D。不能仅放大背景图，角色仍被锁在一屏内。
- `game_state.gd` 当前存档严格要求已知字段、已知地点。新剧情状态必须给旧存档提供默认值并做版本迁移；不能让“继续游戏”突然失效，也不能要求用户重新跑基地剧情。
- 外勤状态独立于「静默回路」枚举，不通过改回旧任务状态实现新战斗。继续复用现有 HP/MP、道具、装备和回合制规则。
- 关卡进度和地图改变必须保存；存档读回后，一次性经验、救援奖励和宝箱不能重复领取。

## 10. 验收：真正能体现探索自由的检查

- 基地电梯可进入可行走的飞船舱；取消登舰不会出航，登舰后到达着陆点。
- B/C/D 的六种访问顺序都能完成任务，不要求重开游戏。
- 至少能完成一条全程不强制战斗的主目标路线；MP 为 0、背包空、未穿赤线均不会软锁。
- 至少三个交互改变地图/角色状态：灯标、救援、修桥；关闭再读档仍保持。
- 玩家能发现一个没有被主任务要求的地点并得到独立反馈或奖励。
- 危险与不可逆处置提前说明；离开、绕行和中途返航始终有可用路径。
- 老存档升级后保留角色资源、旧主线、罗老板选择，并能接到新任务。
- 原 B7 两条结局、原战斗、装备和存档测试继续通过。

确认本稿的区域方向后，再制作分区地图和逐段接入游戏。推荐先交付「电梯—飞船舱—出航—着陆点—返航」闭环，再增加分支探索，最后接入观测站结算。
